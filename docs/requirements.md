# 要件定義書（初版）— 軽音楽同好会 練習室予約・バンド募集アプリ

- 版: v0.1（Sprint 0 時点）
- 更新日: 2026-09-29
- 状態: 予約機能のみ詳細化済み。バンド募集・認証は今後のスプリントで詳細化する

---

## 1. ビジョン

芝浦工業大学 軽音楽同好会（部員50人以上）の部員が、**所属しているのに練習できない状況をなくし**、学年や面識に関係なく**バンドを組みやすくする**。

### 解決する課題

| 課題 | 現状 | このアプリでの解決方針 |
|---|---|---|
| 練習室予約 | TimeTreeで予約している。ライブ前の規制が守られない。規制前の予約との不公平がある | ルールをシステムが自動で強制する。規制期間を事前に登録できるようにする |
| バンド募集 | Discordで実名募集している。レベル感・雰囲気・募集状況が分からず、先輩の募集に応募しにくい | 募集情報を構造化して表示する。応募のハードルを下げる仕組みを作る |
| 誰が誰か分からない | LINE/Discordでは本名や顔が分からない | 部員だけが見られるプロフィール（学年・パート・アイコン） |

## 2. 利用者（ロール）

| ロール | 説明 |
|---|---|
| 部員 | ログインできる全メンバー。個人練の予約、閲覧ができる |
| バンドメンバー | バンドに所属する部員。そのバンドとしてバンド練を予約できる |
| 役員（管理者） | 規制期間の設定、部員・バンドの管理ができる |

## 3. 予約機能

### 3.1 前提

- 練習室は **1部屋**
- 利用できる時間は **7:00〜22:00**
- 予約は **10分単位**（例：3限終了15:00のあと、15:10開始で予約できる）
- 予約の種類は **個人練** と **バンド練** の2つ

### 3.2 予約ルール

| 項目 | 通常時 | 規制期間 |
|---|---|---|
| 個人練の上限時間 | 1回 2時間 | 1回 1時間（役員が設定） |
| バンド練の上限時間 | 1回 2時間 | 1回 1時間30分（役員が設定） |
| 回数制限（個人練） | 1人 1日1回 | 1人 1日1回 |
| 回数制限（バンド練） | 1バンド 1日1回 | 1バンド 1日1回 |
| 延長 | 当日のみ、直後の枠が空いていれば延長できる | 延長できない（仮） |
| 何日先まで予約できるか | 制限なし（バイトや講義に合わせて予定を立てられるようにするため） | 同左 |

補足:
- 個人練とバンド練は別々に数える。1人が同じ日に個人練1回と、所属する各バンドのバンド練をそれぞれ1回ずつ入れられる
- 延長は同じ予約の終了時刻を延ばす扱いとし、新しい予約としては数えない

### 3.3 規制期間の運用

1. 役員はライブの日程が決まった時点で、規制期間（開始日・終了日・種類ごとの上限時間）を**事前に登録**できる
2. 登録された期間の予約は、最初から規制に沿った長さでしか作れない
3. 規制期間を登録した時点で、それに違反する既存の予約がある場合:
   1. システムが違反している予約を一覧にする
   2. 対象の予約者に「期限までに短縮してください」と通知する
   3. 期限までに変更されなければ、**開始時刻はそのままで、終了時刻を上限まで自動で短縮する**
4. 目的は平等性の確保。規制は例外なく全員に適用する

### 3.4 ユーザーストーリー

| ID | ストーリー | 受け入れ条件 |
|---|---|---|
| R1 | 部員として、練習室の空き状況を見たい。練習日程を決めるため | 日ごとに7:00〜22:00の予約状況が表示される。予約者（個人名またはバンド名）と種類が分かる |
| R2 | 部員として、個人練を予約したい | 10分単位で開始・終了時刻を指定できる。他の予約と重なる時間は予約できない。過去の時刻は予約できない。7:00〜22:00の範囲外は予約できない |
| R3 | バンドメンバーとして、バンド練を予約したい | 自分が所属するバンドを選んで予約できる。条件はR2と同じ |
| R4 | 部員として、ルールが自動で守られてほしい。不公平をなくすため | 上限時間・1日1回の制限を超える予約はエラーになり、理由が表示される |
| R5 | 部員として、当日に空いていれば練習を延長したい | 当日かつ通常時のみ、直後の時間が空いていれば10分単位で終了時刻を延ばせる |
| R6 | 部員として、自分の予約を変更・キャンセルしたい | 本人（バンド練の場合はそのバンドのメンバー）だけが変更・キャンセルできる |
| R7 | 役員として、規制期間を事前に登録したい | 開始日・終了日・個人練とバンド練それぞれの上限時間を設定できる |
| R8 | 役員として、規制に違反する既存の予約を公平に処理したい | 違反予約の一覧が出る。対象者に通知が届く。期限を過ぎると終了時刻が自動で短縮される |
| R9 | 部員として、自分の予約を一覧で確認したい | 自分の個人練と、所属バンドのバンド練が一覧で表示される |

## 4. 認証・プロフィール（Sprint 1で詳細化）

- Googleアカウントでログインする（対象アカウントの範囲は要検討）
- プロフィール: 表示名、本名、学年、パート、アイコン画像
- ログインしていない人には何も表示しない

## 5. バンド募集機能（Sprint 5以降で詳細化）

アイデア段階:
- 募集カードの項目: 募集中／締切、曲・ジャンル、募集パート、レベル感、雰囲気・目的（ガチ／エンジョイ、出演予定のライブ）
- パート・学年での絞り込み
- 「興味あり」ボタンで、DMを送る前に気軽に意思表示できる
- 募集で結成したバンドを、そのまま予約用のバンドとして登録できる

## 6. 非機能要件

| 項目 | 内容 |
|---|---|
| 技術構成 | バックエンド Python（FastAPI, SQLAlchemy, Alembic）/ フロントエンド TypeScript（Vite）/ DB MySQL / Docker |
| インフラ | ローカル（Docker Compose）→ AWS EC2 → RDS + S3 + CloudFront の順に段階的に移行 |
| 公開範囲 | 部員限定。個人情報（本名・顔写真）は外部に公開しない |
| 利用端末 | スマートフォンのブラウザで使いやすいこと |
| 時刻 | 日本時間（Asia/Tokyo）で扱う |
| 開発手法 | アジャイル（1週間スプリント、GitHub Issues / Projects で管理） |
